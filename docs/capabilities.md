# 宿主能力与降级

> 本文件定义协议所需的宿主能力、缺失时的降级路径，以及适配层的边界。
> 原语见 [`protocol.md`](./protocol.md)，隔离细节见 [`visibility.md`](./visibility.md)。

## 1. 原则

- 协议**声明能力需求**；宿主提供则用、缺失则**优雅降级**（R2/R12）。
- **缺失能力不得阻止一场团跑通**——只影响隔离强度或交互方式。
- **适配层只提供能力，不解读目录**（D6）：Pi/dsh 插件暴露下述能力；冒险目录**始终由 LLM 读**。

## 2. 能力声明

| 能力 | 用途 | 缺失时降级 |
|---|---|---|
| `spawn-subagent` | 每角色独立上下文子代理 | master 内联扮演，隔离靠纪律 |
| `human-input` | 人类担任角色 | 不支持（前期全 agent） |
| `context-isolation` | 强制隔离角色上下文 | 文件位置 + 投射仍生效，但同上下文内可能泄漏 |
| `tool-gating` | 按角色限制可用工具 | 约定遵守 |

### 2.1 `spawn-subagent`

- **有**：master 为每个角色派生独立上下文子代理，各子代理只读自己的 `roles/<id>/context.jsonl`，隔离由宿主强制。
- **无**：master 在**同一上下文内联扮演**所有角色；隔离退化为「可见性纪律」（见 [`visibility.md`](./visibility.md) §6）。

### 2.2 `human-input`

- **有**：允许人类担任某个角色，协议预留**暂停 / 输入 / 恢复**接口。
- **无**：**前期全部由 agent 担任角色**，不阻塞。

### 2.3 `context-isolation`

- **有**：宿主强制角色上下文隔离，投影泄漏被宿主兜底。
- **无**：文件位置 + `context build` 投射**仍然生效**，但若同处一个上下文，理论上可能泄漏。

### 2.4 `tool-gating`

- **有**：按角色限制可用工具（例如 PL 不可调用 master 专用工具）。
- **无**：退化为**约定遵守**（文档与 persona 中约定）。

## 3. 降级矩阵

| 宿主形态 | spawn-subagent | human-input | context-isolation | tool-gating | 结果 |
|---|---|---|---|---|---|
| 完整能力宿主（如 Pi 原生 sub-agent） | 有 | 可选 | 有 | 有 | 最强隔离 |
| 无子代理宿主（如 dsh 无 project-level sub-agent 面） | 无 | 可选 | 视宿主 | 视宿主 | 内联降级，隔离靠纪律 |
| 最小宿主（纯对话） | 无 | 无 | 无 | 无 | 内联降级，全 agent，靠纪律 |

无论哪一行，**同一份冒险目录都能跑完同一场团**（AC5）；区别只在隔离强度与人类参与。

## 4. 适配层边界

- **适配层（Pi/dsh 插件）不属于框架仓库也不属于冒险目录**，它是宿主侧的能力提供者。
- 它**只提供能力**：人类介入、子代理派生、上下文隔离、工具门控。
- 它**不解读冒险目录**：目录的结构与推进方式始终由 LLM 阅读 `AGENTS.md` 与 `docs/` 决定。
- 本阶段（I1）**不实现**任何适配插件；协议只定义能力声明与降级路径。

- 旧实现无法降级、必须整体运行；新协议在缺失能力时可内联跑通。
